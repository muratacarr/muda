# ADR 0003: Persistent state machine, one active job in the database

Status: accepted

**Decision.** `JobState` transitions are an explicit table (`ensure_transition`), every change writes a
`JobEvent`, and "at most one active job" is enforced twice: in the service for a friendly error and by a
partial unique index (`uq_one_active_job`) so even buggy code cannot create two. Telegram update ids are
primary keys in `processed_updates`, making redelivery a no-op (no second job, no second AI charge).

**Cancellation.** The persisted `cancel_requested` flag is the source of truth; an `asyncio.Event` only
wakes the worker early. `PUBLISHING` is not cancellable; publish and cancel are serialized by
`BEGIN IMMEDIATE`, so exactly one wins.

**Recovery.** On start, interrupted `PROCESSING` jobs become `FAILED/INTERRUPTED` instead of being
retried, because the AI call may already have been billed.

**Trade-offs.** Autogenerated Alembic migrations do not see expression indexes; the index is declared by
hand in migration `0001` and covered by a test that runs the real migration.
